## Installed-package checks

Upgraded the existing test appliance to `fastdup-0.6.4-1.el10.x86_64`, retaining
its repository and share. Stopped SMB and the repository cleanly for the update.
Repository, agent, WebUI and Samba services all became active after installation.
SELinux remained enforcing.

- The approximately 50 GiB Metadata filesystem mounted with the default
  64 GiB Small-File request automatically reduced to **10,723,576,832 bytes**.
  Telemetry recorded both requested and effective limits. The earlier manual
  quota override was removed.
- An empty share with a decimal 10 TB quota reported **10,000,000,000,000 bytes
  total and free** through SMB, despite a smaller physical DATA filesystem.
- An anonymous SMB session successfully created and removed nested directories
  below the existing `VeeamZIP` directory. This reproduces the operation that
  previously returned access denied.
- Created a temporary SMB account through the real privileged-agent API and
  a private share requiring encryption. Anonymous access was rejected.
- Authenticated SMB directory creation, a 1 MiB file write, hash-verified readback
  and deletion succeeded. Free space decreased by exactly 1 MiB after allocation.
- Removed the temporary test account and share, stopped the isolated diagnostic
  Samba instance, and retained the production services.

The complete Veeam backup job was not run by this qualification. The reported
`CreateDirectory` failure was reproduced and its fix verified at the SMB boundary.
The CPU measurements are kernel microbenchmarks, not an SMB throughput claim.
